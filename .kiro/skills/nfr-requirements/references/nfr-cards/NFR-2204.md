# NFR-2204 — The resources of the system are regularly monitored, analysed and in ad equation with the current needs of the application

## 1. NFR Metadata

- **ID:** NFR-2204
- **Title:** The resources of the system are regularly monitored, analysed and in ad equation with the current needs of the application
- **Primary Category:** Performance Efficiency

---

## 2. Executive Summary

- **The "Goal":** The tools for monitoring the resources are implemented on the system. Legacy perimeter: PSA Standard tools: MARS for the collect, PACIFIC dashboard for data request, CARAIBE for capacity planning.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Performance Efficiency standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Tools are automatically implemented with the system.
The analyses must be regularly done during the operation and maintenance phase.
A tracking of the QOS (Quality Of Service) must be done. Implementation depends on the BIS and the application.
- On Cloud platforms (AWS, AZURE, GCP …)
- Resources must be scaled up or down automatically to provision or remove resources when necessary.
- Alerts (mail or PSASM incident) must be setup when limits are reached or any malfunction
- For Kubernetes context, you can set up metrics with Prometheus, monitoring URLs, tracking statistics and resources used under Grafana
