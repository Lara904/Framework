# NFR-6204 — Evolutions of system's versions must be registered

## 1. NFR Metadata

- **ID:** NFR-6204
- **Title:** Evolutions of system's versions must be registered
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** This provision aims to contextualise and share all application modifications between the different actors (BIS, MOA, CAST, etc.). Its implementation means the implementation of a procedure for contextualising changes (validation circuit, method for registering, etc.).
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- This provision aims to contextualise and share all application modifications between the different actors (BIS, MOA, CAST, etc.).
Its implementation means the implementation of a procedure for contextualising changes (validation circuit, method for registering, etc.).
- Cloud context: as soon as there is a technical upgrade on a particular product or component of the platform, you must save the current configuration in case of backtracking

Realization:
Cloud context : technical backup of the architecture for the possibility of reversing in case of anomaly, part carried out by the teams of infra
- On AWS: If you use AWS tools properly, any upgrade is automatically registered in AWS. But you must use the Change API to open a TRACE change automatically, to have the information in SDI too.
