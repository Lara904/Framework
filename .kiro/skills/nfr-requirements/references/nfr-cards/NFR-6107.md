# NFR-6107 — Active network services must be limited to what is strictly necessary

## 1. NFR Metadata

- **ID:** NFR-6107
- **Title:** Active network services must be limited to what is strictly necessary
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** Active network services must be limited to what is strictly necessary. Cloud context: each application is in its network, the architecture also allows sharing, it will restrict access to people who do not have the rights and resources of if they are connected.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Active network services must be limited to what is strictly necessary.
- Cloud context: each application is in its network, the architecture also allows sharing, it will restrict access to people who do not have the rights and resources of if they are connected.

Realization:
- Cloud context: each user will have specific rights to limit the impact on production and error handling. When deploying the application see in which network situation we are, you have at our disposal a bridge and overlay mode
- On AWS: Put all objects and servers in a private VPC (Virtual Private Cloud). Only a “bastion” server should be accessible through a public VPC. Beware the Security Groups: they are here to help improve your security too.
