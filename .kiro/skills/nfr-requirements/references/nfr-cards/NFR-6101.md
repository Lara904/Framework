# NFR-6101 — Exchanges must be encrypted

## 1. NFR Metadata

- **ID:** NFR-6101
- **Title:** Exchanges must be encrypted
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** This is not to make intelligible listening of data as it travels in a network (PSA network, Internet, Non PSA network, etc ...). This cannot be achieved encryption functions.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- This is not to make intelligible listening of data as it travels in a network (PSA network, Internet, Non PSA network, etc ...). This cannot be achieved encryption functions.
- Typically the PSA infrastructure supports this feature through SSL components R / proxies and VPN. We must therefore ensure that access to the application is made through this type of component.
- Regarding external accommodation of all or part of the application we must ensure that the host offers services equivalent to those of the PSA infrastructure.
