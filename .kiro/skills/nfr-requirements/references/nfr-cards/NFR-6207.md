# NFR-6207 — The system ensures the operational integrity of its data

## 1. NFR Metadata

- **ID:** NFR-6207
- **Title:** The system ensures the operational integrity of its data
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** The integrity of data is verified by the application depending on the business sector rules. If the integrity of data needs to be permanent then data should only be able to be altered by authorised procedures (procedures that guarantee the respect of integrity rules) If the integrity of data can be temporarily lowered then batch procedures that can correct the differences need to be implemented.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- The integrity of data is verified by the application depending on the business sector rules. If the integrity of data needs to be permanent then data should only be able to be altered by authorised procedures (procedures that guarantee the respect of integrity rules) If the integrity of data can be temporarily lowered then batch procedures that can correct the differences need to be implemented.
- Live data and traceability data may be concerned by this requirement, depending on the DICT.
- Cloud context: data integrity is the responsibility of the project manager; he only knows what he integrates into the database. He will have access to verify this as he sees fit. If it detects incorrect database data, it can request a database restore

Realization:
- Cloud context: Give specific right to the project manager to enable him to perform data checks. In the event of an anomaly, a database restoration and the processes will have to be restarted after correction before or after the application.
