# NFR-6501 — System's access right policy is defined (named owner, access services ...) and managed

## 1. NFR Metadata

- **ID:** NFR-6501
- **Title:** System's access right policy is defined (named owner, access services ...) and managed
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** The application data is the property of project owner management. The application owner defines the access rights management policy, scope and people involved.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- The application data is the property of project owner management.
The application owner defines the access rights management policy, scope and people involved. This includes both functional as well as technical access rights. 

Realization:
- Method to assign access rights in REUNIS:
- The owner delegates to ASL (Administrateurs de Sécurité Logique) / (Logical Security Administrators), the right to assign access rights to its application.
- The owner validates all the assignment requests made by the ASL.
- Method to assign access rights outside REUNIS: 
This method is to be avoided unless it is implemented in addition to an assignment through REUNIS and to refine the rights that are too complex to be managed by the ASL.

The (PFA or POA) owner refines the user access rights directly in the application. The application should be able to trace this assignment mode
