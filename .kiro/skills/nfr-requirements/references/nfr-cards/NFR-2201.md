# NFR-2201 — The system has a purging procedure for functional data, using data archive if required

## 1. NFR Metadata

- **ID:** NFR-2201
- **Title:** The system has a purging procedure for functional data, using data archive if required
- **Primary Category:** Performance Efficiency

---

## 2. Executive Summary

- **The "Goal":** If there is no purging procedure, the data volume may increase and become incompatible with functioning processing time (batch processing, backup, TP response time). Realization: The physical cleaning and database archiving process should be operational from the go-live of application and planned regularly in everyday life.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Performance Efficiency standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- If there is no purging procedure, the data volume may increase and become incompatible with functioning processing time (batch processing, backup, TP response time).

Realization:
- The physical cleaning and database archiving process should be operational from the go-live of application and planned regularly in everyday life. 

As with any other processing, their planning should be automatic.
- On Cloud platforms (AWS, AZURE, GCP …)
- Use cloud provider services to manage archiving old data
- (AWS: Glacier, Azure: Storage Archive Access …)
