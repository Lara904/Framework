# NFR-6503 — All users (human or technical like batch …) for who an authentication is needed must be authenticated with the current logical security tool

## 1. NFR Metadata

- **ID:** NFR-6503
- **Title:** All users (human or technical like batch …) for who an authentication is needed must be authenticated with the current logical security tool
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** In the PSA security rules implementation for protecting the network and data access, the entire access to the Group information should be controlled. Realization: Entire data can only be accessed by the known users from our directories (except Grand Public application).
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- In the PSA security rules implementation for protecting the network and data access, the entire access to the Group information should be controlled. 

Realization:
- Entire data can only be accessed by the known users from our directories (except Grand Public application).
The user identification and authentication should be done by the logical security tool in place.
- Any intervener (user, pilot, administrator or other) works with his single and unique PSA Id, excluding any generic or specific account. The cases of impossibility should be a waiver request at the entity in charge of Administration Centrale de Sécurité Logique (ISSI /ACSL) / Logical Security Central Administration.
- Any task that is not triggered by a person for his own use (e.g. case of « automates », i.e. the processes run without human intervention) should be managed through a PSA Id « of service » defined in co-ordination with the entity in charge of Administration Centrale de Sécurité Logique (ISSI /ACSL) / Logical Security Central Administration. The password of this service account should follow the password policy.
- Each « automate » should have its own PSA Id so that its rights are limited to just the needs of actions assigned to it. In OS UNIX environments, this Id should not allow opening interactive connections. The tasks should operate with this Id in no login mode.
- The submission of work is done for PSA Id account whose rights, administered in REUNIS (Reférentiel UNIque de Sécurité), are limited to the job.
