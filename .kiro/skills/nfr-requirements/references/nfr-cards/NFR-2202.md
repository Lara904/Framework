# NFR-2202 — The system has purging procedures for technical data

## 1. NFR Metadata

- **ID:** NFR-2202
- **Title:** The system has purging procedures for technical data
- **Primary Category:** Performance Efficiency

---

## 2. Executive Summary

- **The "Goal":** If there is no purging procedure, the data volume may increase and become incompatible with functioning processing time (batch processing, backup, TP response time). On Cloud platforms (AWS, AZURE, GCP …) Use cloud provider services to manage your data lifecycle.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Performance Efficiency standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- The physical cleaning and database archiving process should be operational from the go-live of application and planned regularly in Operation and Maintenance phase. 
As with any other processing, their planning should be automatic.
- On Cloud platforms (AWS, AZURE, GCP …)
- A purge of technical data, logs or any other technical data is the responsibility of project team and implemented by the OPS.
- If the retention period by default on this data is not sufficient,
- You can use the cloud provider purge process by services as AZURE Data explorer, Amazon Data lifecycle Manager for application data and AWS CloudWatch/CloudTrail / Azure monitor LOG for technical data.
