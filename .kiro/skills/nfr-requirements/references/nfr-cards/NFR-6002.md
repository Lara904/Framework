# NFR-6002 — Source code control, search for vulnerabilities in the code and penetration testing are done

## 1. NFR Metadata

- **ID:** NFR-6002
- **Title:** Source code control, search for vulnerabilities in the code and penetration testing are done
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** Source code control (e.g. for outsourced developments: compilation of code by the technical integrators): This provision aims to limit the possible problems associated to malicious development.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Source code control (e.g. for outsourced developments: compilation of code by the technical integrators):
- This provision aims to limit the possible problems associated to malicious development. Through increased traceability and easier audits of codes, this provision contributes to dissuasion. Furthermore, a guarantee of the compilation environment allows a reduction in the possibility of introducing "malware" into the application.
- Its implementation can, in particular, be based on the JIP integration platform for JAVA technology.
- Search for vulnerabilities in the code and penetration tests:
- An application vulnerability is a system flaw or weakness in an application that could be exploited to compromise the security of the application (e.g. SQL injection, Cross-Site Scripting …).
- This control is under the responsibility and funding of the project team and is performed by the security teams (e.g. ISSI/OTAS).
- It can be done for all application, but is mandatory only if D, I or C >=3.
