# NFR-7101 — The batchs must be designed and developed in modular way in consistent functional subset

## 1. NFR Metadata

- **ID:** NFR-7101
- **Title:** The batchs must be designed and developed in modular way in consistent functional subset
- **Primary Category:** Maintainability

---

## 2. Executive Summary

- **The "Goal":** The batchs must be designed and developed in modular way in consistent functional subset. All job treatment must be planned or provoked.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Maintainability standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- The batchs must be designed and developed in modular way in consistent functional subset. All job treatment must be planned or provoked.
- Cloud context: Under Docker, a process equals a container, in order to have a better follow-up and to avoid putting everything in the same container, use scalability. Each application service is containerized which will allow having x containers

Realizations:
- Technical or applicative treatment must separate. The error of one technical treatment do not impact applicative treatment (vice versa). 
An error of execution can be reengaged
- Cloud context: in the event of an anomaly or a container crash, it automatically reboots itself according to its configuration. It is necessary to differentiate an application process from a technique, a technical process in error will always have the functional application
