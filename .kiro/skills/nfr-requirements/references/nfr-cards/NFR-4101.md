# NFR-4101 — The system proposes useful languages for the user interface

## 1. NFR Metadata

- **ID:** NFR-4101
- **Title:** The system proposes useful languages for the user interface
- **Primary Category:** Usability

---

## 2. Executive Summary

- **The "Goal":** For systems used in more than one country, the user interfaces may need to exist in corresponding languages. The functional specifications must details all elements about the user interface languages management: The list of available languages, The way to choose the displayed language (automatic by detecting the OS languages or any other user preference, a parameter in the user’s account, some graphical element like flags or a list to select the language …)
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Usability standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- In the functional specifications and in the mock-ups, generally only one language is visible on screens, messages, printed documents …
- As it is not easy to write all texts versions for all available languages in a Word specifications document, in Enterprise Architect or in a mock-up, writing them in an Excel file is easier.
- This Excel file must have one row for each text and one column for each language, so different translators can work to fill it.

**Impacted deliverables:** Functional Specifications Dossier, Mock-up
