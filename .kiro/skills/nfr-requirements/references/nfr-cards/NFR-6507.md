# NFR-6507 — The system uses the right method to authenticate users

## 1. NFR Metadata

- **ID:** NFR-6507
- **Title:** The system uses the right method to authenticate users
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** Access to any non-public information requires identification of the user. The necessary means to prove identity are linked to the level of sensitivity of the information to be accessed.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- To avoid strong adherence between the application and authentication technologies, the implementation of Identity's federation protocol is required whenever it is technically possible. The identity federation standards allowed for user authentication are (Oauth2, SAML V2, ADFS).
- Implementation Federation documentation:
- How to implement OpenId Connect /OAuth 2.0  with SeedStack:
- Questionnaire OIDC/Oauth:
- Questionnaire SAML:
- Using of identity federation standards (Oauth2, SAML V2, ADFS) for user authentication when applications are in the cloud is also  required to avoid  credential theft.
- Note: The enhanced authentication or strong in practice is requested for access to the application, but is only required for access to sensitive functions, in particular when the provision is due to the presence of DCP.
- On Cloud platforms (AWS, AZURE, GCP …):
- All servers and databases must be in a Private VPC, only a “bastion” server with port 22 (ssh) open can be accessible through a public VPC. All connections to a website must be made through https.
- Connect everyone from Stellantis active directory to your application using fedateted SSO: Ping Fedatede at Stellantis.
