# NFR-5103 — Process scheduling must be fully automatic

## 1. NFR Metadata

- **ID:** NFR-5103
- **Title:** Process scheduling must be fully automatic
- **Primary Category:** Reliability

---

## 2. Executive Summary

- **The "Goal":** Automate the planning and delete the manual operations on operating objects, possible error sources. Realization: Use scheduler (without mixing) and automation tools: z/OS: TWS
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Reliability standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Automate the planning and delete the manual operations on operating objects, possible error sources.

Realization:
- Use scheduler (without mixing) and automation tools:
- Open: $Universe (Unix, Windows, VMS), cron (Unix), Netbatch (Tandem), Task Scheduler (Windows)
- Steer the features of the application within the application itself. 
Pre-requisites: A steering application system authorizes the steering of application by the user.
- Cloud context: It is mandatory to use a specific container for scheduling treatments. Moreover, for each operating treatment, it’s mandatory to have the template in Ansible Tower even if this treatment is scheduled.
