# NFR-5301 — Any application batch program must generate a return code reflecting its execution end status

## 1. NFR Metadata

- **ID:** NFR-5301
- **Title:** Any application batch program must generate a return code reflecting its execution end status
- **Primary Category:** Reliability

---

## 2. Executive Summary

- **The "Goal":** (See document for details.)
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Reliability standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- It is related only to batch programs.

Detail:
- A program, which ends correctly, must send a return code set to zero.
A program which ends abnormally sends a return code different than zero (z/OS particularities: refer § « Realization, z/OS case »).
The return code reflects the status of end of execution of program, but does not control further processing. Its non-null value requires processing stop.

Within a planning entity, application logic must not be expressed in the command languages (JCL, Shell, Perl, and TACL); the batch processing must be simple and harmonized.
- Cloud context: return codes for application processing are supported by the code and developed by the developers. Return code 3 causes the application to crash, a return code 1 generates a warning, and if a process is successful, it generates a return code of 0.

Realization:
- Application logic is defined through the programs by use of files, databases, monitoring tables.
The execution reports of programs must be deported in result files, sysout or log, serving only the expertise in case of problems.
Permissible exceptions are derived from software.
- Cloud context: the generation of return codes is under the responsibility of the developers of the application. The configuration of the transition when a processing goes into error is done by SDI-Link and an incident is configured by the OPS.

z/OS Case:
- In z/OS, the concept of return code is coupled to the concept of abend code. Any program ending abnormally must generate an abend code, which helps to stop the current job.
