# NFR-1410 — The configuration of the DB must respect the SOX compliance rules

## 1. NFR Metadata

- **ID:** NFR-1410
- **Title:** The configuration of the DB must respect the SOX compliance rules
- **Primary Category:** Functional Suitability

---

## 2. Executive Summary

- **The "Goal":** Security should be integrated with Stellantis IAM tools (LDAP or Identify federation), so password rules are following Stellantis password policy. No local accounts are allowed.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Functional Suitability standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Case Oracle DB on premise:
- For ORACLE, there is a model change that allows (via script execution from Oracle Manager Enterprise console OEM) to validate if the DB is SOX compliant.
- This model change must be used. It includes the steps and evidences required for SOX:
- There are some requirements needed to be in place, for planning and executing a change for SOX Oracle database analysis:
- The unix server hosting the Oracle database must be registered and reachable from Oracle OEM console: https://yval2eu0.inetpsa.com:7803/em - IVCINDSECU and ESO/DBDC teams can be engaged for support
- The unix server hosting the Oracle database must have the Oracle OEM agent installed. IVCINDSECU and ESO/DBDC teams can be engaged for support
- The Oracle database must be accessible as sysdba from OS-unix account “oracle”.
- Case other DBs:
- For other DBs (other than Oracle on premise), they should be integrated with LDAP for user and password authentication and avoid using local accounts. In case LDAP integration is not possible specific password policy must be documented and implemented in-line with the Stellantis Password policy.
- For any questions or support, please contact SOX ICT infrastructure team.

### Reference Links
