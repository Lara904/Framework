# NFR-6509 — SOX Access right and segregation of duties are properly implemented

## 1. NFR Metadata

- **ID:** NFR-6509
- **Title:** SOX Access right and segregation of duties are properly implemented
- **Primary Category:** Functional Suitability

---

## 2. Executive Summary

- **The "Goal":** Each application should be integrated with REUNIS to give access to users. SOD (Segregation Of Duties) is a principle to respect to ensure same user to develop and deliver in production the object he has self-developed.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Functional Suitability standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- For audited (SOX or CAC) applications, SA must respect following rules:
- All technical integration SA must be sensitive.
- All sensitive SA mustn’t be part of a GOAL and granted individually to user.
- Globally, we ensure there is no SOD conflicts doing UAR on application’s SAs.
- One same user must not have in same time SA for developing the application and SA for production delivery.
- For SAP applications, several reports are executed every 1st day of each month on SAP central server Solution Manager:
- 2 for the technical integration (INDUS SAP SOP report and TPALOG report)
- 1 for the PGA (PGA SAP SOP) report.
