# NFR-5304 — IT Hardware redundancy (server farms, clusters, etc.) is implemented

## 1. NFR Metadata

- **ID:** NFR-5304
- **Title:** IT Hardware redundancy (server farms, clusters, etc.) is implemented
- **Primary Category:** Reliability

---

## 2. Executive Summary

- **The "Goal":** (See document for details.)
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Reliability standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Criteria not applicable for applications without redundant hardware.

Detail:
- This provision aims to cover a breakdown in IT hardware, in order to ensure the continuity of the service despite the unavailability of one of its components (server, storage array, router, switch, etc.).
The provisions implemented to meet this requirement are of a "high availability" type (based on the redundancy of IT hardware).
For further details, please see this page.

The switch must be implemented and tested. It is about testing the correct switch of hardware like cluster, loaded network hardware (ACE card type) from the switch to another server, secondary disk array (non exhaustive list), in order to validate the correct installation of all the products and application after switch.

NB: in the documents meant for operations, the equipment’s linked to (PLCs) must be designated by their network name.
- On Cloud platforms (AWS, AZURE, GCP …)
- You must ensure you have implemented the redundancy on the critical features of your application.
- Particularly for IAAS implementation.
- For SAAS this feature is usually integrated in the SLA with the integrator.
- Use preferably managed services to have redundancy automatically managed.
- The system integrator performs the test, then performs it in operations (in collaboration with the implantation site of the machine and system experts if necessary), in pre-production context.
There must also be a network outage to check the switch.
This switch test is to be re-performed on the production machine by the operations, to validate the correct installation of all the products.
It is to be re-performed on the production machine by the operations, a while before the start-up, to ensure that the procedure is always valid after the possible corrections.
