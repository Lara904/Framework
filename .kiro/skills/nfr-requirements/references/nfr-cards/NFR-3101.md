# NFR-3101 — The system is able to coexist with others

## 1. NFR Metadata

- **ID:** NFR-3101
- **Title:** The system is able to coexist with others
- **Primary Category:** Compatibility

---

## 2. Executive Summary

- **The "Goal":** Development subsidiaries, hardware and products:
Development field of an application (except strategical orientation) must be part of authorized PSA sector. The hardware and products used by the application are approved or exempted, and meet the operation and development criteria, which are related to them (stop/restart, possible switch, monitoring, compliance of coding standards, backups/restorations).
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Compatibility standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Application of a strategical plan of development technologies.
Application of approval procedure.
- IT project manager must:
- Take into account from design of existing infrastructure services
- Prepare the application to facilitate integration in Stellantis infrastructure.
- Avoid developing or putting in service modules, which perform the functions of infrastructure services, especially when they are shared.
- Case of applications concessions or subsidiaries:
- The project must in this case be responsible for the request for concessions or subsidiaries using hardware configurations and/or minimal software enabling the applications to function.
- On Cloud platforms (AWS, AZURE, GCP …)
- Each application is independent. It will be necessary to ensure that the technical architecture is able to handle this situation. See with the architects (Stellantis and integrator ones) for specifics recommendations.
- Environments are dedicated and dataproof. Objects must be identified with “TAGS”.
