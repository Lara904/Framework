# NFR-2101 — The target system architecture is able to meet performance expectations and performance has to be monitored during the RUN

## 1. NFR Metadata

- **ID:** NFR-2101
- **Title:** The target system architecture is able to meet performance expectations and performance has to be monitored during the RUN
- **Primary Category:** Performance Efficiency

---

## 2. Executive Summary

- **The "Goal":** The check is done at various levels: In pre-production to validate the good performance in application load; In ramp-up phase to prevent any drift.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Performance Efficiency standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Natively, the metrology / capacity tracking tools are installed from the machine configuration (open domain, except « calcul »). On z/OS, the tools also exist on all the machines (PACIFIC).

These tools provide measures that can be used at different phases of project life cycle:
- Performance test result in preproduction;
- Service quality monitoring in the ramp-up;
- Service quality monitoring in Operation and Maintenance phase.
- MARS/ILOT is the device installed consistently for all the dedicated services. SMF/MICS is equivalent for z/OS.
The indicators provided are used through client applications provided by MACP.
PACIFIC is the general view interface.
- ATLANTIQUE is the service quality-monitoring tool.
In pre-production, the performance tests are to be conducted to simulate an expected behaviour in production. The performance tests are conducted using specific tools provided by MACP (Performance Center, Avalanche device ...).
Note: the performance test execution on a mutualised preproduction should be strictly supervised for the following reasons: representativeness of performance test and risk of collateral impact on other pre-productions.
- Cloud context: pre-defined scenarios will be realized as well as verification of the architecture of the tested platform, memory, CPU, load. Dashboard must be created in Graphana for On Premise or CloudWatch for AWS. These dashboards must represent the memory, CPU consumption and all useful elements.
