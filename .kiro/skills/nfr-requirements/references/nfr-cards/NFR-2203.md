# NFR-2203 — The system has an operational procedure to re-organize the database(s)

## 1. NFR Metadata

- **ID:** NFR-2203
- **Title:** The system has an operational procedure to re-organize the database(s)
- **Primary Category:** Performance Efficiency

---

## 2. Executive Summary

- **The "Goal":** (See document for details.)
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Performance Efficiency standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- Not applicable for applications without database (DOMINO, …).

Detail:
- The procedure to re-organize the base should be set up, by specifying the realization frequency.
- The need to implement a re-organization should be studied even if some DBMS offer bases that are not disorganized.
- If a re-organization of the base cannot be implemented (e.g.: re-organization time is very long because of high volume of the base), the procedure results in an indication of actions that help to avoid any disorganization.
- This criterion affects infrastructure because the disorganization of a base often results in increased response time, indicator practically always present in the partnership contract and on the value for which the infrastructure is committed.
- On Cloud platforms (AWS, AZURE, GCP …)
- Use cloud provider managed services for databases to integrate automatically the reorganization.
- (AWS: Aurora, RDS, RedShift, DynamoDB, ElastiCache
- Azure: SQL Server, AZURE CosmoDB, Azure database for MariaDB, Azure database for PostgreSQL …).
- If you did not use the cloud provider data managed services, you must implement you reorganization process.
