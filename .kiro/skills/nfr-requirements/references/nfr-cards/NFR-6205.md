# NFR-6205 — Technical configuration's modifications must be registered

## 1. NFR Metadata

- **ID:** NFR-6205
- **Title:** Technical configuration's modifications must be registered
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** These provisions aim to contextualize and share all changes to environment, system or application, for application between the different actors (MOA, BIS, INFRA, etc.). Its implementation means the implementation of a procedure for contextualizing changes (validation circuit, method for registering, etc.).
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- On cloud provider: A role back processing for technical configuration is automatic and tested before any modification. Be sure the role back process is mastered by the project team.
- If you use AWS, AZURE or GCP tools properly, any upgrade is automatically registered in cloud provider.
- You must use the Change API to open a TRACE change automatically, to have the information in PSASM too.
