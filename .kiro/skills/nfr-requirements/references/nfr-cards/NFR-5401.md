# NFR-5401 — The system includes a tested operational back-up and recovery mechanism

## 1. NFR Metadata

- **ID:** NFR-5401
- **Title:** The system includes a tested operational back-up and recovery mechanism
- **Primary Category:** Reliability

---

## 2. Executive Summary

- **The "Goal":** The backup strategy is developed from the preliminary study. Implement and test the restoration feature.
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Reliability standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- The restoration test is executed (through change) in pre-production before the application kick-off (without altering the objects between the test time and the kick-off).
- z/OS Case (outside USS): 
The System integrator produces backup files, which are automatically set in a pool, save based on their coding.
- OPEN Case: 
The System integrator should follow the criteria stated in the basic principles document - Criteria of operability (Refer SSSD site)
- Cloud context: during the pre-production phase, tests including backup and recovery will be tested. It will be necessary to be able to trace an application from end to end.
