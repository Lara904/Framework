# NFR-6502 — Administration of user rights complies with the current logical security tool

## 1. NFR Metadata

- **ID:** NFR-6502
- **Title:** Administration of user rights complies with the current logical security tool
- **Primary Category:** Security

---

## 2. Executive Summary

- **The "Goal":** No users or user rights administration can be done outside REUNIS, for the systems when one of the values of DICT is greater than 1. The administration of rights of an application involves all the application users and thus necessarily: System integrators Studies
- **Why it matters:** Failure to implement this NFR may result in non-compliance with Security standards, increased operational risk, and potential rejection during technical control gates (TCC/CTC).

---

## 3. Technical Requirements

### Key Constraints

- No users or user rights administration can be done outside REUNIS, for the systems when one of the values of DICT is greater than 1.
The administration of rights of an application involves all the application users and thus necessarily:
- PFA of the application (under MOA or AMOA responsibility)
- POA(s) of application (according to the organization)
- Internal or third party end users
- To request access, refer to the documents put in links.

Recommendation: The functional acceptance of the application should be done with the business profiles and not with generic profiles. 

Realization:
- For each profile involved, the developer defines a package of rights in his application. For each package of rights, an access service corresponds in REUNIS. 

He defines the scope of using each access service if required. 

Recommendation: REUNIS manages the recoverable access rights reducing the number of access services to be created.
- The rights that every technical or functional user can exercise are granted through REUNIS access services. They are validated in the security server of technical domain hosting the application. All the files, all the databases and all their tables are controlled access, validated at the time of access by the security server of technical domain that hosts them.
- The user authentication (PSA Id and password) should never be managed by the application. Only the host systems authorized by ISSI (portals, proxies, system processes, SAP …) are authorized to manage the authentication process (request to especially input the password). For specific request, the « APIs » are provided by DSIN, within the entity responsible for Prevention and Management of IT risks (ISSI).
- The requests presented to REUNIS should use the « APIs » provided by DSIN (ISSI). No application request should be led directly on the access control base (LDAP, AD, TSS or other).
